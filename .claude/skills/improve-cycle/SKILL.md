# 개선 사이클 (총괄 = 메인 세션이 실행)

규칙은 `CLAUDE.md`, 형식은 `docs/feedback/README.md`. 사용자는 초보 개발자이므로 진행 상황을 한국어로 짧게 알린다.
에이전트는 `.claude/agents/` 의 정의를 `subagent_type` 으로 지정해 실행한다 (critic, reviewer, collector, processor, frontend, alerts, ops).

## 0. 준비
- `.venv/Scripts/python tools/check.py` 로 현재 상태가 초록인지 확인. 빨강이면 사이클을 멈추고 먼저 그 문제를 고친다.
- 최신 실제 데이터 확보: `.venv/Scripts/python collect.py --no-alerts`.

## 1. 비판 — critic 1개
프롬프트에 포함: 라운드 번호(= `docs/feedback/rounds/` 파일 수 + 1), 오늘 날짜, 사용자가 준 초점(있으면).
결과 파일을 읽는다.

## 2. 분류 — 총괄이 직접
- `BACKLOG.md` 에 새 항목을 옮기고 상태 지정. 재오픈 요청·반박도 검토.
- 채택 기준: P0·P1 우선 → 비용 대비 효과 큰 P2. **한 사이클 최대 6개.** 사용자 손이 필요한 것(토큰 등록 등)은 `보류` + 사용자에게 알림.
- 규칙 위반 제안(우회 등)과 근거 없는 항목은 `기각` + 사유.
- 공통 파일(`models.py`, `http.py`, `collect.py`) 변경이 필요한 항목은 총괄이 먼저 처리한 뒤 담당에게 넘긴다.
- 채택 항목이 영역 경계를 넘으면 쪼갠다 (예: 카테고리 = processor 가 필드 생성 → frontend 가 필터).
  의존 관계가 있는 항목은 순서대로, 없는 항목은 병렬로.

## 3. 개선 — 담당 에이전트 병렬
- 같은 파일을 두 에이전트에게 동시에 주지 않는다. 같은 영역 항목은 한 에이전트에 묶는다.
- collector 는 사이트 묶음별로 여러 개 가능 (파일이 겹치지 않으므로).
- 프롬프트에 포함: 항목 ID·문제·근거·완료 기준 원문, 수정 허용 파일 목록, "동의하지 않으면 반론을 근거와 함께 보고해도 된다".
- 결과의 `제안`(영역 밖 변경 요청)은 총괄이 판단해 직접 반영하거나 다음 사이클로.
- 상태를 `진행중` → `완료` 로 갱신. 반론이 온 항목은 총괄이 근거를 보고 `기각`/`재배정` 결정.

## 4. 검증 — reviewer 1개
완료 항목 전체를 넘긴다 (ID, 완료 기준, 담당 보고 요약).
- `통과` → `검증됨`
- `재작업` → 같은 담당에게 사유와 함께 1회 재배정 → 다시 reviewer. 2번째도 실패하면 `보류` + 사용자에게 보고.

## 5. 마무리
- `.venv/Scripts/python tools/check.py --live` 최종 확인.
- `BACKLOG.md` 최종 상태 반영.
- 사용자 보고(짧게): 이번 라운드에서 지적된 것 / 고친 것(검증됨) / 기각·보류한 것과 이유 / 사용자가 해야 할 일.
- 커밋·푸시는 사용자 허락을 받고 한다 (푸시하면 15분 내 실제 사이트에 반영됨).
