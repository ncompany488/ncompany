### C-1-1 용량 표기가 있냐 없냐로 같은 상품이 2~3개로 쪼개짐 (사용자 핵심 요구 '신라면 5/10/20개 = 같은 상품' 실패)
- 심각도: P1
- 영역: processor
- 근거:
  - `hotdeal/product.py:201-202` — 개수가 있으면 키에 **개당 용량**(`|120g`)을 붙이고, 용량이 없으면 안 붙이고, 개수 없이 무게만 있으면 `|100g` 을 붙임 → 같은 상품이 최대 3개 키로 흩어짐.
  - 실제 history: 이름이 같은데 키가 여러 개인 경우 **87개**. 예:
    - `신라면|120g` ← "[쿠팡] 농심 신라면 120g x 20입 (5,060원)" / `신라면` ← "[쿠팡] 신라면 5개 (2,400원)", "[네이버] 농심 신라면 20입 (12,690원)"
    - `삼양라면|120g`(3건) / `삼양라면`(4건), `생생우동|253g`(5) / `생생우동`(2), `짜슐랭|145g`(4) / `짜슐랭`(1), `열라면|120g`(3) / `열라면`(1),
      `금강만두육개장|630g` / `금강만두육개장`, `더미식백미밥|210g` / `더미식백미밥`, `육식토끼닭가슴살소시지|80g` / `…소시지`
    - `초코파이48p|1872g`(4) / `초코파이48p|100g`(2) / `초코파이48p`(2) — 같은 '초코파이 48P 1872g' 가 "1박스" 유무로 개수모드·무게모드로 갈림.
  - 'N+M' 은 개수가 없으면 무게 합으로 바뀜 (`product.py:168`): "햇반 210g 1+1" → 키 `햇반|100g`(420g) 인데 "햇반 210g 24개" 는 `햇반|210g`. "스팸 200g 5+1" → `스팸|100g`.
  - 위 87개 중 표본 25개를 손으로 보면 약 절반(12개)이 '용량 표기만 빠진 같은 상품'이고 나머지는 실제로 다른 개당 용량(암바사 345ml vs 1.5L 등, 이건 맞게 분리).
- 문제: 사용자가 든 예시 그대로(신라면 5개 2,400원 vs 120g×20입 5,060원) 서로의 최저가를 못 봄. 89.7% 상품이 기록 1건인 주요 원인 중 하나.
- 제안: 키의 기본은 '이름'만으로 하고 개당 용량은 속성(tier)으로. 용량 없는 글은 같은 이름 상품의 개당 용량이 하나뿐이면 거기에 붙이고, 여러 개면 별도 표시. 'N+M' 은 개당 용량이 있으면 개수(N+M개)로 처리. 무게모드 ↔ 개수모드는 `개당 용량 × 개수 = 총량` 으로 서로 환산 가능할 때 같은 상품으로.
- 완료 기준: (1) `tests/test_product.py` 에 아래 쌍이 '같은 상품(같은 pid)' 으로 통과 — "신라면 5개"/"농심 신라면 120g x 20입", "삼양라면 20개"/"삼양라면 120g 10개", "햇반 210g 1+1"/"햇반 210g 24개", "초코파이 48P 1872g"/"초코파이 48P 1872g 1박스". (2) 같은 history 로 다시 집계했을 때 '이름 같고 키 여러 개' 중 용량 표기 유무 차이만 있는 경우 0건 (전/후 수치 보고).
